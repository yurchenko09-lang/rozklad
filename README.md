# Розклад — GitHub Pages версія

Ця версія розкладу оновлюється сама, без Claude і без ручного втручання:
GitHub Actions за розкладом (кожні ~30 хв) сам заходить у Google Таблиці
коледжу, перечитує дані і зберігає їх у `data/schedule.json`. Сторінка
(`index.html`) читає цей файл — все відбувається на самому GitHub, без жодного
"підтвердження", яке потрібне було в попередньому варіанті.

## Встановлення (одноразово)

1. **Створіть новий репозиторій** на GitHub (Public — для безкоштовного
   GitHub Pages потрібен публічний репозиторій, якщо у вас немає платного
   акаунту). Назва — будь-яка, наприклад `rozklad`.

2. **Завантажте туди всі файли з цього архіву**, зберігаючи структуру папок
   (`.github/workflows/update.yml`, `scripts/update_schedule.py`,
   `data/schedule.json`, `index.html`, цей `README.md`).

   Найпростіше — через веб-інтерфейс GitHub: "Add file" → "Upload files",
   перетягнути все одразу (GitHub сам розкладе по папках, якщо зберегти
   шляхи). Або через git, якщо звично:
   ```
   git init
   git remote add origin https://github.com/<ваш-акаунт>/<назва-репо>.git
   git add .
   git commit -m "Initial import"
   git branch -M main
   git push -u origin main
   ```

3. **Дозвольте Actions писати в репозиторій**: Settings → Actions → General →
   розділ "Workflow permissions" → оберіть **"Read and write permissions"** →
   Save. Без цього кроку автооновлення не зможе зберігати нові дані.

4. **Увімкніть GitHub Pages**: Settings → Pages → Source: **"Deploy from a
   branch"** → Branch: **main**, папка **/ (root)** → Save. За хвилину-дві
   GitHub покаже посилання на сторінку (виду
   `https://<ваш-акаунт>.github.io/<назва-репо>/`).

5. **Запустіть перше оновлення вручну**: вкладка **Actions** → зліва
   "Оновити розклад" → праворуч кнопка **"Run workflow"** → Run workflow.
   Через хвилину перевірте, що зʼявився новий коміт у `data/schedule.json`.

Далі workflow сам спрацьовуватиме кожні ~30 хвилин — без вас і без Claude.

## Як це влаштовано

- `scripts/update_schedule.py` — читає ті самі 6 таблиць коледжу (по одній
  на день тижня), парсить розклад на сьогодні і 6 днів наперед, перевіряє
  дату в заголовку кожної вкладки (щоб не записати застарілі чи ще не
  опубліковані дані), і за можливості підставляє номери аудиторій з третьої
  вкладки — якщо і там дата збігається.
- Дати в минулому ніколи не перезаписуються.
- Якщо в якийсь конкретний запуск Google Таблиці недоступні чи ще не
  оновлені — файл даних просто лишається таким, яким був; наступний запуск
  спробує ще раз.

## Обмеження, про які варто знати

- Формат таблиць коледжу час від часу трохи "стрибає" (інший порядок
  колонок, зсунуті рядки) — скрипт розпізнає найпоширеніший, стабільний
  формат, який спостерігався востаннє. Якщо колись розклад на сторінці
  раптом виглядатиме дивно — найімовірніше, коледж змінив структуру таблиці,
  і `scripts/update_schedule.py` варто буде підправити під новий формат.
- Це окрема, самостійна система — вона ніяк не повʼязана з попередньою
  сторінкою в Claude (Artifact). Якщо хочете лишити стару сторінку як є,
  просто не оновлюйте на неї посилання; якщо хочете повністю перейти на цю
  версію — розсилайте студентам нове посилання GitHub Pages.
